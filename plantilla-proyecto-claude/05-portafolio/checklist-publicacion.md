# Checklist antes de publicar el proyecto (GitHub / LinkedIn / aigis-cloud.com)

- [ ] README con: qué hace, por qué existe, cómo correrlo en 3 comandos (idealmente `docker-compose up`).
- [ ] Dockerfile / docker-compose.yml si aplica (ver `02-proyecto-activo/entorno-y-herramientas.md`).
- [ ] Sin secretos ni credenciales en el historial de git (`.env` ignorado, `.env.example` incluido).
- [ ] Diagrama simple de arquitectura (aunque sea 5 cajas) — ayuda muchísimo a reclutadores.
- [ ] Sección "qué aprendí / qué decisiones tomé" — linkea a tu `decisiones-tecnicas.md` resumido.
- [ ] Tags/topics del repo alineados a tu posicionamiento (ai-engineer, rag, llm, cloud-security, etc.).
- [ ] Publicar en LinkedIn con 3-4 líneas: problema, solución, stack, aprendizaje. Sin jerga vacía.
- [ ] Si aplica, agregarlo a la sección de proyectos destacados de aigis-cloud.com.
